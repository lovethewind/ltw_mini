# 小程序富文本渲染修复

## 问题

小程序使用 Towxml 展示 Markdown 时，块级节点之间的格式换行被输出为独立的 `<text>` 节点。微信渲染会按正文行高处理这些换行，导致标题、段落和列表之间出现异常大间距；`view` 对 `list-item/list-style` 的支持也不稳定，使无序列表项目符号与文字错位。

## 修复

- Towxml 解析时过滤块级格式换行，`pre/code` 内部换行继续保留。
- 无序/有序列表取消对小程序不稳定的 `list-style` 依赖；项目符号或编号合并到每项第一个文字节点（遇到 `**加粗**` 时进入 `strong` 的文字节点），避免标记在 `decode` 子组件边界消失或单独换行；代码高亮使用的行号列表恢复原布局。
- 代码块中的普通空格、连续空格和 Tab 统一转换为不可折叠空格；Markdown 与 HTML 代码块都执行该规范化，复制/高亮前仍还原为空格。
- 真机编辑长正文时，问题不只在 `maxlength`：部分客户端会在 textarea 异步挂载/赋值时按默认 140 字截断初始值。编辑页先用 `editorReady` 延迟挂载，再通过独立的 `editorValue` 在 nextTick 重新写入，并拦截挂载期间的截断事件；`maxlength="100000"` 只负责输入上限。
- 表格和单元格显式设置高对比边框、白色（深色主题为深色）底色及表头背景，避免页面蓝色背景和默认边框吞掉网格线。
- 将 Towxml 基础样式直接引入 `decode` 和表格子组件，并使用共享样式隔离；列表项目符号改为递归节点中的文本前缀，避免子组件块级布局造成再次换行。
- 笔记和文章详情的浅色页面背景调整为更淡的蓝白色，降低正文阅读时的视觉干扰。
- 增加节点、代码换行和 WXSS 选择器回归测试。
